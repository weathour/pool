## 一、一句话

**一个 git 仓库，装三样东西：数据、规则、机制。**

```
一个 git 仓库
├── 数据  五份 JSONL（谁需要什么、交了什么、谁该得多少、谁是谁、维护者做了什么）
├── 规则  policies.jsonl 十一条
└── 机制  tools/ 十个工具 + CI + 钩子
```

**仓库之外只有一样东西：每个人自己的私钥。**

**这三样走的是同一套流程** —— 这是设计里最要紧的一点：

```
改数据（提一张单）  → 开 issue → 提 PR → 校验 → 复核 → 合并
改规则（改一条门槛）→ 开 issue → 提 PR → 校验 → 复核 → 合并   ← 同一套
改机制（改校验器）  → 开 issue → 提 PR → 校验 → 复核 → 合并   ← 同一套
```

**所以"规则怎么改"的答案，和"怎么交一份东西"是同一个答案。**
而且规则和机制的每次改动都留在 git 历史里，带理由、带签名。

## 二、它要解决什么

| 问题 | 不解决的后果 | 对应 |
|---|---|---|
| 别人攒的东西我看不到 | 整理出来的东西只有一个人知道怎么用 | **仓库** |
| 我想找人做事，找不到人 | 只能靠熟人介绍，陌生人进不来 | **公告板** |
| 做了事没人知道 | 干多干少一个样，干的人慢慢就不干了 | **账本** |

**一句话：把资料、经验、和处理资料的方法放进一个公共的地方，并且给"想一起做事的人"一个不用互相认识也能对接的入口。**

## 三、一次协作的完整流程

```
① 开 issue（用「开一张单」表单，强制填"怎么算做完了"）
        ↓
② 本地跑 tools/sign 追加记录 → 用自己私钥签（★ 自动的，不需要他操作）
        ↓
③ 提 PR
        ↓
④ CI 跑 tools/validate（链 + 签名 + 11 条规则）
        ↓
⑤ ★ 另一个人复核（不能是自己）—— 他在这里估"别人从零做要多久"
        ↓
⑥ 开单人确认
        ↓
⑦ 合并进 main = 入库 + 上账，一次完成
        ↓
⑧ 自动镜像到公开仓库
```

## 四、数据长什么样

**五份纯文本，一行一条 JSON。记事本就能打开。**

| 文件 | 记什么 |
|---|---|
| `requests.jsonl` | 公告板：谁需要什么 |
| `deliverables.jsonl` | 交付物与复核 |
| `credits.jsonl` | 账本 |
| `keyring.jsonl` | 公钥目录（**不是成员名单**） |
| `maintainer-log.jsonl` | 异议、回应、权限变更 |

**每条记录的通用字段：**

```jsonc
{
  "seq":  42,                  // 本文件内递增
  "at":   "2026-09-16T17:03+08:00",
  "by":   "ed25519:ab12...",   // ★ 身份是公钥，不是账号
  "prev": "sha256:...",        // 上一条的 hash
  "sig":  "ed25519:...",       // 对 hash 的签名
  "hash": "sha256:..."         // 只覆盖内容，不覆盖 seq/prev
}
```

**★ `hash` 只覆盖内容，不覆盖 `seq`/`prev`** —— 这是为了让多人合并成为可能：
两个人同时追加 → 冲突 → 重排重链 → **内容没变，所以签名仍然有效，不需要任何人的私钥。**

**★ `keyring.jsonl` 不是成员名单，是公钥目录。** 区别很重要：
- 名单 = 有边界、要审批、进不去就用不了
- **目录 = 没有边界，任何人加一条自己的记录就能开始干活**

**而且"移除"也不需要**：密钥丢了或人走了，加一条 `status: retired` 就行。**历史记录里的签名永远有效，因为它当时确实是他签的。**

## 五、四层防护，各管一件事

| 层 | 管什么 | 谁提供 |
|---|---|---|
| **git commit 链** | 发布、分发、顺序 | git 自己 |
| **文件内哈希链（`prev`）** | **数据脱离 git 也能自证** | 我们 |
| **Ed25519 签名** | 是谁写的、防抵赖 | 我们 |
| **签名 tag + `.allowed_signers`** | 独立时间锚点，别人可验 | git + 我们 |

**四者不重复。** git 管分发，链管自证，签名管人，tag 管时间。

## 六、credit 是什么（详解见 [`02-credit.md`](02-credit.md)）

**不是分数，是一份由三个人联署的认可记录：**

| 谁签 | 签什么 |
|---|---|
| 交付的人 | "这个是我做的" |
| 复核的人 | "我看过了，它值 X" |
| 开单的人 | "它确实能用" |

```
定基     = 复核者估的复现时间 ÷ 10        ← ★ 定价权在复核者手里，不在做事的人手里
复用加成 = ×(1 + min(引用次数, 5) × 0.2)
提问版税 = 引发的产物 credit × 20%（上限 200）
门槛     = 复核通过（复核者 ≠ 交付者）+ 开单人确认
```

**两个防作弊都是结构性的，不靠稽查：**

1. **自己闭环拿不到 credit** —— 复核者必须 ≠ 交付者
2. **复用无法伪造** —— 次数从 `links` **推导**，不由任何人自报。**只有别人交付时 `--link` 你的产物，你才能领加成。**

**为什么盯"复用"：** 引用别人要先读懂它。**没人会为了给别人刷分去读一个没用的东西。**

**credit 现在什么都换不到。** 它真正有含义的那天，是它开始决定"谁掏服务器钱"的那天。

## 七、它刻意不是什么

| 不是 | 为什么 |
|---|---|
| **不是币** | 不转让、不兑换、不上链。上链的四个好处三个不需要、一个是红线 |
| **不是社群** | 社群是容器，记录才是目的。**把搭组织当成做事是它最可能死的方式** |
| **不是排行榜** | 不做用户主页、不做排名。credit 不该参与任何决策 |
| **不是数据库应用** | 数据是纯文本，clone 就能读，比任何 API 都直接 |
| **不追求去中心化** | 语料里有专章论证"去中心化救不了科层化"。**头头的第一人称意识本来就是去中心的** |

## 八、已经实测验证过的性质

**这些不是"设计成"，是"验过"：**

| 性质 | 怎么验的 |
|---|---|
| **篡改可被发现** | 改一个字段 → 校验器报 `hash 与内容不符` |
| **断链可被发现** | 删掉中间一条 → 报 `prev 对不上` |
| **重链后签名仍有效** | 合并冲突 → `resolve --write` → 校验通过，签名全好 |
| **自己批自己被拒** | 交付者复核自己的东西 → `p-003` 拒绝 |
| **credit 真的会入账** | 账本里有真实数字，每条带签名 |
| **复用无法伪造** | 次数从 `links` 推导；`sign reuse` 造不出加成 |
| **外人能独立验证** | **从公开仓库 clone → 校验通过 → tag 签名 Good** |
| **新人上手成本** | 机械步骤 **0.8 秒**；真成本在写出可判定的验收标准 |
| **"只追加"拦住了作者本人** | 我手动改账本，当场被判 `hash 与内容不符` |

## 九、边界（不遮掩）

| 边界 | 说明 |
|---|---|
| **能防伪造，防不了敷衍** | 签名证明"某人说过"，证明不了"他真的看过"。**"复用"补一半 —— 它让敷衍留下痕迹** |
| **11 条规则只覆盖形式条件** | 复核者是否真的独立判断过，机器查不了 |
| **时间戳靠 git tag 签名** | 不是区块链 |
| **Gitea 是单点** | 机器关了协作就停摆（内容还在） |
| **镜像不是实时的** | 等于你最后一次 push 时的状态 |
| **没有第二个人** | 目前所有活动都是作者一个人的。**这是最大的缺口** |

## 十、这个项目最可能怎么死

**不是技术问题。** 技术侧已经跑通了。最可能的是这两条：

**① 把搭组织当成做事**

> 花三个月讨论元老院和 credit 的机制，而池子没有变大。

语料自己给这件事命名过：`organization for practice by itself`（把组织本身误当实践）。

**② 前端从"窗口"变成"目的"**

> 前端功能越来越多，`data/` 的字段开始跟着"前端要显示什么"长，
> 而不是跟着"什么算一条记录"长。

**这两条的共同点是：它们都让人感觉在推进。**

**判据很简单：池子里有没有新的记录，以及有没有东西被别人引用。**

## 一句话

> **一个 git 仓库，装数据、规则、机制三样，走同一套流程。**
> **签名代替权限 —— 没有账号、没有白名单、没有管理员。**
> **仓库外面只有一样东西：你自己的私钥。**
> **而它活着还是死了，只看两个数：新记录的速度、和被引用的次数。**
