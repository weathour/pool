## 二、今天就能做的：本地跑通两个人的完整流程

**不需要服务器、不需要域名、不需要 Cloudflare。** 就你的机器。

### 第 1 步：开一张真单子

开一张**对你现在真的有价值**的单子。不要用测试数据——**这一步的价值全在"真实"上**。

```bash
cd <仓库>

python3 tools/sign req \
  --kind question \
  --title "……" \
  --spec "……" \
  --acceptance "……"
```

**★ 卡在哪一步告诉我。** 尤其是 `--acceptance`——如果你写的时候觉得"这没法判定"，那正是要发现的问题。

### 第 2 步：模拟第二个人

用另一个 handle 造一个第二身份，走完"交付 → 复核 → 确认"：

```bash
# 第二个人加入
python3 tools/sign init --handle 测试者

# 他接单
python3 tools/sign --handle 测试者 claim r-0001

# 他交付
python3 tools/sign --handle 测试者 deliver \
  --request r-0001 --kind question --content-file 产物.json

# 你自己复核（你是另一个人，所以合规）
python3 tools/sign review d-0001 \
  --result pass --reason "……" --reproduce-minutes 30

# 开单人确认
python3 tools/sign confirm r-0001
```

**★ 第 2 步验证的是那个关键问题：** 你（作为复核者）**只看 `spec` 和 `acceptance` 两栏，能不能判定这东西合不合格？**

- **能判** → 整套设计成立
- **判不了** → 是 `acceptance` 写得不够清楚，**回去改写法，不要往下走**

### 第 3 步：清掉测试痕迹

```bash

python3 tools/validate      # 应当恢复通过
```

## 三、接下来要装的（按顺序）

### 第 4 步：Gitea（协作层）

**为什么需要它：** 现在只有你能操作。要别人参与，需要一个能收 issue / PR 的地方。

```bash
mkdir -p ~/gitea && cd ~/gitea

docker run -d --name gitea \
  --restart unless-stopped \
  -p 3000:3000 -p 2222:22 \
  -v ~/gitea/data:/data \
  -v /etc/timezone:/etc/timezone:ro \
  -v /etc/localtime:/etc/localtime:ro \
  -e USER_UID=1000 -e USER_GID=1000 \
  gitea/gitea:latest
```

然后访问 `http://localhost:3000` 完成初始化：

| 项 | 填什么 |
|---|---|
| 数据库 | **SQLite3**（一个文件，备份简单） |
| 站点名称 | 池子 |
| 管理员账号 | 用那个统一邮箱，用户名建议 `JiaWeathour` |
| SSH 端口 | `2222` |
| HTTP 端口 | `3000` |

**★ 初始化完成后立刻做一件事：备份 Gitea 数据。**

```bash
# Gitea 的数据全在 ~/gitea/data 里
tar czf ~/gitea-backup-$(date +%F).tar.gz -C ~/gitea data
```

**为什么重要：** 本地 `data/*.jsonl` 是**内容真相**，但 **issue、PR、评论、CODEOWNERS 配置都在 Gitea 里**。这两份备份要分开放。

### 第 5 步：把仓库推上去

```bash
cd <仓库>
git remote add origin http://localhost:3000/JiaWeathour/pool.git
git push -u origin main
```

（先在 Gitea 网页上建一个**空的**仓库 `pool`，不要勾选初始化 README。）

### 第 6 步：Cloudflare Tunnel（让外面能访问）

```bash
# 安装
curl -L --output cloudflared.deb \
  https://github.com/cloudflare/cloudflared/releases/latest/download/cloudflared-linux-amd64.deb
sudo dpkg -i cloudflared.deb

# 登录（会打开浏览器，用那个统一邮箱的 Cloudflare 账号）
cloudflared tunnel login

# 建隧道
cloudflared tunnel create pool

# 配置：把 git.你的域名 指向本机 3000
mkdir -p ~/.cloudflared
cat > ~/.cloudflared/config.yml <<'EOF'
tunnel: pool
credentials-file: <家目录>/.cloudflared/<tunnel-id>.json
ingress:
  - hostname: git.你的域名
    service: http://localhost:3000
  - service: http_status:404
EOF

# 绑定域名并启动
cloudflared tunnel route dns pool git.你的域名
sudo cloudflared service install
```

**★ 注意：这一步需要域名。** 你说先不买——那就先跳到第 8 步，等域名到手再做。

**不想买域名的临时办法：** `cloudflared tunnel --url http://localhost:3000` 会给你一个随机 `trycloudflare.com` 地址，**能立刻测试，但每次重启都会变**。适合验证流程，不适合长期。

### 第 7 步：Gitea 自动推镜像到 GitHub

在 Gitea 仓库的 **设置 → 仓库 → 镜像设置** 里：

| 项 | 填什么 |
|---|---|
| 镜像类型 | **推送**（Push） |
| 远程地址 | `https://github.com/你的账号/pool.git` |
| 授权 | 一个 GitHub Personal Access Token（勾 `repo`） |
| 同步间隔 | 8 小时（或手动触发） |

**★ 方向不能反：Gitea → GitHub。GitHub 那份是只读副本，权威永远在 Gitea。**

**这一步一石三鸟：** 有镜像（防篡改的核心）+ Pages 能构建 + 多一个分发口。

### 第 8 步：Cloudflare Pages

1. Cloudflare 控制台 → **Workers & Pages** → **创建** → **Pages** → **连接到 Git**
2. 选那个 GitHub 镜像仓库
3. 构建设置：

| 项 | 值 |
|---|---|
| 框架预设 | 无 |
| 构建命令 | `python3 tools/build-site`（还没写，先留空） |
| 输出目录 | `site` |

**★ 展示站点的生成器（`tools/build-site`）我还没写。** 它要做的事很简单：把四份 JSONL 渲染成一个静态 HTML（公告板 + 账本 + 验证说明）。
