# 上链成本测算

> 已定：走区块链。本文只算成本，并给出落地方案。
> **结论先说：成本取决于一个二选一，两者差 1000 倍以上——**
> **只锚 Merkle root：约 ¥10/年。全部数据上链：约 ¥1000～10,000/年，且隐私不可恢复。**

---

## 一、★ 这个二选一是决定性的

| | **方案 A：锚定（只上哈希）** | **方案 B：数据上链（全部记录）** |
|---|---|---|
| 链上写什么 | **32 字节的 Merkle root** | 每条 credit 记录（含 member、amount、reason） |
| 每周期交易数 | 1 | 几十条 |
| 隐私 | **零暴露**（一个哈希读不出任何东西） | **member + 余额永久公开** |
| 可读性 | 本地 JSONL 全文可读 | 链上数据要写工具才能读 |
| 改错 | 本地 append `amend`，重新锚一次 | **链上只能再发一条修正，永久带污点** |
| 是否涉及金融 | **否**（存证） | 边界模糊（地址间转移的记录） |
| 年成本 | **≈ ¥10** | **¥1,000 ～ 10,000+** |
| 换方案的代价 | 随时能加 | **已上链数据删不掉** |

**★ 关键：这个决定不能反悔。** 一旦数据上链，它永久公开、永久不可删、永久带污点。**而锚定方案随时可以升级成数据上链——所以正确顺序是先锚定。**

**我强烈建议 A。** 下面把两种都算清，你自己看。

---

## 二、链上单位成本的现状（2026）

| 链 | 一笔简单交易 | 说明 |
|---|---|---|
| **比特币 L1** | $0.5 ～ 5 | 只适合极低频锚定 |
| **以太坊 L1** | $0.5 ～ 5 | 同上，且 gas 波动大 |
| **Base / Arbitrum / Optimism（L2）** | **$0.01 ～ 0.05** | 锚定方案的合理选择 |
| **Solana** | **< $0.001** | 最便宜，生态较杂 |
| **OpenTimestamps（聚合锚到比特币）** | **免费** | 它把上万个哈希打成一个交易，成本由它承担 |

**注意最后一行。** OpenTimestamps 的做法是：**你提交哈希，它聚合，它付钱，你免费。** 你拿到一份 `.ots` 证明文件，之后可以自行验证（验证需要跑一次比特币节点或调 API）。

**这就是"只锚哈希"的极致形态，成本是零。**

## 三、方案 A 成本精算

### 3.1 触发频率（不需要每笔都锚）

| 触发 | 频率 | 说明 |
|---|---|---|
| 周期结算 | 4 次/年 | 每个周期末尾锚一次 Merkle root |
| 成员状态变更 | ~4 次/年 | 加人、退出、换钥 |
| 规则变更 | ~4 次/年 | 改 credit 定价、衰减参数 |

**合计约 12 次/年。** 不需要每次操作都锚——因为 **`credits.jsonl` 内部的链式哈希已经保证了逐条不可篡改**，锚定只需要证明"到某个时刻为止，这份日志是这个样子"。

### 3.2 成本

| 载体 | 单次 | 年成本（12 次） |
|---|---|---|
| **OpenTimestamps** | **免费** | **¥0** |
| **Base / Arbitrum L2** | ¥0.3 ～ 3 | **¥4 ～ 36** |
| 以太坊 L1 | ¥4 ～ 40 | ¥50 ～ 500 |

**★ 方案 A 的年成本：¥0 ～ 40。可以忽略。**

而且这笔钱连"公摊"都算不上——**一年不到一杯咖啡。**

### 3.3 但真实成本不在这里

**方案 A 的真实成本是维护成本，不是 gas：**

| 项 | 成本 |
|---|---|
| 一个钱包（只管锚定，不放资产） | 0 |
| 备份助记词 | 0（但要记得做） |
| 锚定脚本（算 root → 提交 → 存证明文件） | **约 50 行代码** |
| 验证脚本（拿证明文件验证） | 约 30 行 |
| 国内访问 RPC 的稳定性 | **★ 这是唯一的实际麻烦** |

**★ 最后一条要提醒：** 公共链的 RPC 端点在国内访问不稳定。对策：
- 用境外 VPS 做锚定（于是又回到"要不要租服务器"——**但这里只需要一个最便宜的机器，或者一台常开的本地机器走代理**）
- 或者直接用 OpenTimestamps（它不需要你在链上发交易，只需要提交哈希 + 事后验证）

**这也是我建议 OpenTimestamps 的实际理由：它让你不需要一个常驻的钱包和 RPC 连接。**

## 四、方案 B 成本精算（数据全部上链）

### 4.1 数据量测算

| 项 | 估算 |
|---|---|
| 一条 credit 记录（含 member / amount / reason / refs） | ~150 字节 |
| 每周期 credit 交易数（3～5 人，活跃） | ~20 条 |
| 年记录数 | ~80 条 |

### 4.2 成本

| 链 | 单条 | 年成本（80 条） |
|---|---|---|
| Base / Arbitrum L2 | ¥0.3 ～ 3 | **¥24 ～ 240** |
| 以太坊 L1 | ¥4 ～ 40 | **¥320 ～ 3,200** |
| 比特币 L1（用 OP_RETURN） | ¥5 ～ 50 | **¥400 ～ 4,000** |

**单看钱，方案 B 其实也不算离谱**——L2 上一年也就几百块。

**但钱不是方案 B 的主要成本。** 见下。

### 4.3 ★ 方案 B 的真实成本（无法用钱解决的三项）

| # | 成本 | 严重程度 |
|---|---|---|
| **1** | **隐私永久丧失** | ★★★ **member 与余额永久公开。你们是实名内部池子，地址与人的关联会泄露真实的产出历史。而"内部使用"这个前提正是让整套设计不需要法务的支点——数据上链会打破它** |
| **2** | **改错变成永久污点** | ★★★ credit 一定会算错、会调整。本地可以 `amend`，**链上只能再发一条修正记录，并永久保留错误那条** |
| **3** | **schema 冻结风险** | ★★ 链上数据一旦写入，schema 就不能大改（至少要能永远解析旧格式）。**你们 schema 现在还在 v1，第一个周期后必调** |

**第 1 条是决定性的。** 它不只是隐私问题——它会**摧毁"内部使用"这个前提**，而那个前提是你们目前不需要 ICP 备案、不需要处理版权、不需要法律主体的唯一原因。

---

## 五、我的建议：分两步，先锚后议

```
第 1 步（现在）    周期 Merkle root → OpenTimestamps（免费）
                  或 → Base L2 锚定（¥4～36/年）
                  ★ 只上 32 字节哈希，数据全在本地

第 2 步（将来）    如果确实需要"credit 记录本身可被外部独立验证"
                  再考虑把 credit 记录上链
                  ★ 但那时要先解决隐私：要么用假名地址，
                    要么接受公开，要么放弃
```

**为什么必须先锚后议：**

> **锚定方案随时能升级成数据上链，反过来不行。**
> 已上链的数据删不掉。**先做便宜且可逆的那一半。**

而且第 1 步已经拿到了你想要的大部分东西：**一个外部可验证的时间戳 + 不可篡改证明。** 差的只是"外部人能直接读到 credit 明细"——**而这件事在内部池子里，本来就不需要。**

---

## 六、如果一定要数据上链，四个必做的准备

按重要性排：

| # | 准备 | 说明 |
|---|---|---|
| **1** | **改 schema：先定死，再上链** | 链上格式一旦写入就永久可解析。**现在 schema 还在 v1，先跑完一个周期再定** |
| **2** | **假名地址** | 每人一个独立地址，且**不与真实身份在任何公开处关联**。但注意：地址的资金来源会泄露关联性 |
| **3** | **只上 credit 的"事件"，不上 members** | 成员表留在本地。**member 字段用假名 alias** |
| **4** | **备份助记词 + 演练恢复** | 私钥丢了，链上那些记录就成了没人能签的垃圾 |

**★ 第 1 条意味着：如果决定数据上链，第一个周期必须是"本地跑、不上链"。** 因为 schema 要跑过才知道哪里不对。

---

## 七、一句话

> **只锚 Merkle root：¥0～40/年，隐私零暴露，改错无代价，随时可升级。**
> **数据全上链：¥1,000～10,000/年（含隐性成本），隐私永久丧失、改错永久留痕、schema 被冻结。**
> **两者差 1000 倍，而这个决定不可逆——所以先锚，后议。**
> **而"数据上链"真正的代价不是 gas，是它会打破"内部使用"这个前提——那是你们目前不需要法务的唯一原因。**

---

## 八、需要你确认

1. **锚定还是数据上链？**（我强烈建议锚定）
2. **锚定载体**：OpenTimestamps（免费、无钱包、验证需工具）还是 Base L2（¥4～36/年、需钱包、工具成熟）
3. **如果选 L2**：锚定用的机器放哪（本地走代理 / 境外最便宜 VPS）——**这一条会连带决定要不要租服务器**
4. **确认锚定不需要每次操作都做**，周期末尾一次即可（因为本地哈希链已经保证逐条完整）
