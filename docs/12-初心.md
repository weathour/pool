## 一、我上一版错在哪

我把重心放在"260 个提交、可核验、证明方法论"上，得出"这是一个知识生产项目，社群只是容器"。

**这个读法抓住了资产，但漏了一半。** 漏的是：**这个仓库里的东西是用来被用的，而"被用"需要一个入口。**

你说的三样——**资料、经验、服务**——正好是我漏掉的那一半：

| 你说的 | 我上一版的处理 | 实际地位 |
|---|---|---|
| 资料 | 抓住了（语料、细读卡、主题档案） | 仓库的**存货** |
| **经验** | **完全漏了** | 仓库里**最不可复制**的部分 |
| **服务** | 当成"功能清单" | 其实**就是那个入口** |

**尤其"经验"这个词，我漏得很厉害。** 仓库里真正独有、别人抄不走的东西，不是哲学内容（那是 B 站讲者的），也不是工具代码（那是可复制的），而是：

- **怎么让模型产出可核验结论的那套操作经验**
- 194 个审查条目背后的判断标准
- 27,500 行工具踩过的坑
- 哪些做法是死路、为什么

**"资料"是可以买的，"经验"不能。** 而你们两个人（加上我）在群里讨论的全部内容，本质上都是关于经验怎么传承的问题——只是被包装成了"元老院""准入""credit"。

## 二、按你的原话，把"服务"重新拆开

你在 09-16 的原话是：

> 服务，就是可以提出自己需要什么样的智力或技术然后其他人看到了可以给评价和建议，所以首先是一个**智库**的作用。然后是**硬件基础设施**，考虑起步先用租的服务器，可以有域名之类的，有机器人和资料保存和处理。**设备开发或项目的人员或劳力招募之类的自己贴公告互相联系**。区块链之类的作为货币暂时还不考虑，但是后续大概率要有。

**你列了四样，而且它们不是并列的，是两层：**

### 第一层：仓库（存货 + 供给）

| 项 | 本质 | 特征 |
|---|---|---|
| **智库** | 提问/回答/评价 | 公共品。答案不因被多人看而减少 |
| **硬件基建** | 服务器、域名、机器人、资料处理 | 公摊资源。成本已发生，多一个人用不增加成本 |
| **资料保存与处理** | 语料、卡片、档案、账本 | 存量。越用越值钱 |

### 第二层：协作申请平台（流量 + 匹配）

| 项 | 本质 | 特征 |
|---|---|---|
| **招募板** | 贴公告、互相联系 | **匹配市场。** 需要定价、需要成交、需要清算 |
| （货币） | 结算 | 你说了"后话"，对 |

**"协作申请"这四个字是钥匙。** 它说明这个平台的**发起单位不是"人"，是"需求"和"提议"**：

```
有人提出需要什么  →  其他人看到  →  评价、建议、或加入  →  形成协作
```

**注意这条链里没有"审批者"。** 没有一个机构决定"你能不能来"——**只有"这个需求/提议有没有人接"。**

**这就是我上一版为什么觉得元老院别扭的真正原因：** 元老院管的是"谁能进来"，而你说的机制是"什么东西有人接"。**一个管资格，一个管匹配。你们真正设计的是后者，讨论的却是前者。**

**准入制度是用来解决"匹配失败"的错误的药。** 匹配失败的原因是"没人看得见需求"和"没人信得过对方"，不是"坏人太多"。

## 三、★ 一个关键区别：两层用不同性质的账，混了就两层都废

这是本轮最重要的结构发现。

语料里有一个正好对应的区分：

> 这是纲领，那么最左边是习俗再往那边退就本能了，这上面是 n 行为 n 的行动，那么最往下面就是交易了，交易有对价的行动或者有偿行动。
> —— 庶政学预备工作（1），`library/manifests/shuzheng-practice-agent-reviewed-evidence.jsonl:2`
> （`analysis_status: V`，仅作有界释义）

**纵轴就是"交易（有偿 / 有对价）↔ 无对价行动"。** 而你说的两层，正好落在轴的两端：

| | 仓库层（智库 + 基建 + 资料） | 协作层（招募板 + 结算） |
|---|---|---|
| 行动性质 | **无对价**——我回答你，不图你什么 | **有对价**——我加入你的项目，要拿回报 |
| 能不能定价 | **不能**。定不了"一个好回答值多少钱" | **必须**。不定价就没人来 |
| 记录方式 | 按贡献记账（reputation） | 按成交结算（payment） |
| 失败形态 | 定价了 → 提问变下单，**没人愿意答** | 只记账 → 变互相吹捧，**匹配市场死掉** |

**如果两种账混在一起，两层会同时坏掉。**

- 智库一旦按次计价，就变成"付费问答"——答主会挑问题，问的人会算账，公共品性质消失
- 招募板一旦只记 reputation 不给实际回报，就变成"互相捧场"——没人真去做，市场不成立

**结论：credit 必须分两种，不能是一种。**

| | **贡献值**（仓库层） | **结算额**（协作层） |
|---|---|---|
| 记什么 | 你让公共池变大了多少 | 一次协作里谁该拿多少 |
| 性质 | 不可转让、不可兑换、只增不减 | 可清算、可对价、有债权债务 |
| 用途 | 席位、声誉、话语权重 | 真金白银的分配 |
| 与前文的关系 | = v3 的 credit（双层衰减那套） | **v3 完全没设计，是真空白** |

**我 v1/v2/v3 从头到尾只设计了左边那种，右边的完全没碰。** 而右边的——一次协作怎么定价、怎么分账、有人赖账怎么办——**才是"协作申请平台"能不能成立的核心**。

**这就是为什么"货币还是得纳入建设之初的设计"这句话是对的，而我一直想把它往后推。** 不是理念问题，是**招募板没有结算就只是个留言板**。

## 四、修正后的初心

> **初心：把自己攒下的资料、经验、和处理资料的方法放进一个公共的地方，并且给"想一起做事的人"一个不用互相认识也能对接的入口。**
>
> **两个半句，缺一不可：**
> - 只有仓库 → 别人看完就走，**没人留下**
> - 只有平台 → 热闹但没东西，**变成普通群**

**为什么以前做不到，现在能做了：**

仓库这个东西，一个人做很自然（260 个提交就是证明）。但**"仓库 + 匹配"两件事一起做，历史上只有大组织干得成**——因为匹配的成本（介绍、撮合、定约、验证、催账、处理赖账）是随人数指数上升的。小群体做这个，结果一定是二选一：要么变成死资料库，要么变成活的聊天群加一个没人看的资料夹。

**agent 第一次把这件事的成本结构改了。** 撮合、初筛、验证、记录、催办——这些现在可以自动化。所以"仓库 + 匹配"第一次对三五个人可行。

**这也解释了为什么这是 2026 年的对话，不是 2016 年的。**

而稀缺的那个东西，既不是知识，也不是算力，也不是答案：

> **稀缺的是"陌生人之间的信任"。**

仓库解决了一半：**它让一个人说过的话变成可查的。** 协作申请平台解决另一半：**它让两个人不用先认识就能开始合作。**

**而对照这个目标，邀请制是错的方向。** 邀请制只在**已有熟人网络**里分配信任，它不生产新的信任。**你们要的东西恰恰是"不用互相认识就能对接"——那需要的是可查的记录，不是介绍人。**

## 五、这会把设计改成什么样

| 原设计（v1-v3） | 修正后 |
|---|---|
| 元老院管准入与清退 | **准入不是核心机制。** 核心是"申请与接单"的记录。**人不是被批准的，是被约到的** |
| 三院制 | **两院就够：仓院（管池子）/ 约院（管结算与争议）。** 我上一版砍掉"解释院"是对的，但砍错了理由——不是"多余"，是**它属于仓库层不属于协作层** |
| 一种 credit | **两种账**：贡献值（不可兑换）+ 结算额（可清算）。**这是本轮最大的改动** |
| 先定 charter | **先让"发需求→有人接"这条链跑通一次。** 一次真实成交 > 一份章程 |
| 12 个月日落 | 保留。但真正的死亡信号是：**90 天没有任何"申请-接单"记录** |
| 面向外部卖知识包 | **降级。** 那是变现路径之一，不是初心。初心是**让这个池子被用起来** |

**"服务"这个词现在也清楚了：** 服务不是"我们提供什么"，是**"这个池子能为谁解决什么问题"**。智库服务的是"提问的人"，基建服务的是"要跑东西的人"，招募板服务的是"想找人做事的人"。

**三种服务对应三种人，而他们不需要是同一批人。** 这一条推翻了我之前"成员"的概念——**如果服务对象可以不同，那"成员"这个统一身份本身就是多余的。** 有的是：**提问者、供给者、接单者、复核者。一个人可以同时是四个，但不必先成为"成员"。**

## 六、还有一个被跳过的东西：风险

最后必须提一句群里那句被打断的话。

米波大神问"**你这会不会违法哦**"，雁雁答"自己服务器自己用，违鸡巴法……好像人多了得备案……那也是小事"。

**按这一版的读法，这个问题比雁雁当时的判断重得多。**

因为"**资料仓库**"确实很简单——自己用、备案、没问题。

但"**协作申请平台**"不一样。一旦这个池子开始持续地**发布需求、撮合他人、约定回报、分账结算**，它在功能上就已经是一个**中介**了。中介这件事有它自己的法律形态要求和风险，跟"自己用服务器"不是一回事。

**米波那句不是外行话，是这个设计的第一个硬约束，而且它出现在第一轮讨论里、被当成"小事"跳过了。**

**在动任何代码和服务器之前，"平台在法律上是什么"这个问题必须先有答案。**
