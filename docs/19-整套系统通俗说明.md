# 整套系统：一份通俗说明

> 用大白话讲清现在这个东西是什么、怎么运转、credit 在里面干什么。
> 不含术语，看完应该能自己给别人讲一遍。

---

## 一、一句话：这是两个东西

**一个公告板 + 一个账本。**

- **公告板**：谁需要什么、谁想做什么，贴出来；别人看到了可以接
- **账本**：谁做了、做了多少、什么时候做的，记下来

**其他所有东西——规则、机器人、签名、维护者——都是围着这两个东西转的辅助设施。**

**先记住这句话，后面全部能推出来。**

---

## 二、它要解决什么问题

三个具体的问题：

| 问题 | 不解决的后果 |
|---|---|
| **1. 别人攒的东西我看不到** | 那 363 篇整理、736 张卡片，只有一个人知道怎么用 |
| **2. 我想找人做事，找不到人** | 只能靠熟人介绍，陌生人进不来 |
| **3. 做了事没人知道** | 干多干少一个样，干的人慢慢就不干了 |

**三个问题对应三样东西：仓库、公告板、账本。**

## 三、数据长什么样（技术基础·一）

**没有数据库，没有服务器，没有网站。**

**就是六个文本文件，一行一条记录，放在你自己的硬盘上。**

```
my-pool/
├── data/
│   ├── members.jsonl          谁在这个池子里
│   ├── requests.jsonl         公告板：谁需要什么
│   ├── deliverables.jsonl     公告板：谁交了什么东西
│   ├── credits.jsonl          账本：谁该得多少
│   ├── maintainer-log.jsonl   维护者干了什么（单独记）
│   └── cycles.jsonl           每次结账的总结
```

**`jsonl` 就是"一行一个 JSON"**，用记事本就能打开看。

**每一行长这样**（拿账本举例）：

```json
{"seq":12, "at":"2026-09-20", "prev":"a3f9...", "sig":"ed25519:...",
 "member":"m-0001", "amount":6, "reason":"d-0007 通过复核"}
```

**翻译成人话**：这是账本第 12 条，2026-09-20 写的，上一条是 a3f9 开头的那条，签名是……，m-0001 这个人得了 6 分，因为 d-0007 那件东西通过了复核。

**就这么简单。**

## 四、为什么这样能防赖账（技术基础·二）

两个小机关，各自管一件事：

### 机关一：签名 —— 防"这不是我写的"

每个人有一对钥匙。**自己留一把（私钥），另一把公开（公钥）。**

**你写的每一条记录都用私钥签个名。别人拿你的公钥一验，就知道是不是你写的、有没有被改过。**

效果：**没法冒充别人记账，也没法事后说"这条不是我提的"。**

### 机关二：串链子 —— 防"偷偷改历史"

**每条记录里都写上"上一条的指纹"。**

```
第 1 条 → 指纹 A
第 2 条（写着 A）→ 指纹 B
第 3 条（写着 B）→ 指纹 C
```

**现在如果你想偷偷改第 1 条**：它的指纹就变了 → 第 2 条里写的 A 对不上 → 整条链后面全部对不上。**一改就露。**

**这两个机关加起来，就等于"这本账没法偷偷改"。**

### 那如果是自己改自己的呢

**这是关键问题，答案分两半：**

- **技术管一半**：每条记录都有签名，改了签名就失效
- **人管一半**：**任何成员都能自己把那六个文件拿过来，从头算一遍**，算不对立刻发现

**所以要动账，必须同时骗过所有人 —— 而这在内部池子里不现实。**

### 为什么不放区块链上

**普通情况下的直觉是"上链更保险"。但这里不是：**

| 问题 | 说明 |
|---|---|
| **没必要** | 区块链防的是"互不信任的陌生人"。你们是熟人内部池子，防的是"事后想改账的自己人" |
| **代价大** | credit 连着人名，**上链就是永久公开谁拿了多少** |
| **更严重** | 数据一上链，**"内部使用"这个前提就破了**——而这个前提是你们现在**不需要备案、不需要处理版权、不需要注册公司**的唯一原因 |

**所以：本地六个文件 + git 备份，足够了。** 真要盖章（证明某天账本就是这样），**每周期用签名打个 git 标签就行，一分钟的事，免费。**

## 五、公告板怎么用（管理基础·一）

**一次协作，从头到尾只做四件事：**

| 步骤 | 谁做 | 做什么 |
|---|---|---|
| **1. 开单** | 需要的人 | 说清"缺什么" + **"怎么算做完了"** |
| **2. 接单** | 想做的人 | 认领 |
| **3. 交东西** | 接单的人 | 交上来 |
| **4. 验收** | 另一个人 + 开单的人 | 一个人复核，开单的人确认能用 |

**第 1 步里"怎么算做完了"是必须写的。** 写不出来，这张单子就不合格。

**为什么这条这么重要：** 因为**整套账本可信度的唯一支撑点，就是"验收标准清不清楚"。** 标准清楚，谁来判都一样；标准不清楚，就只能靠人品。

**★ 一个必须说清的要点：单子上不写人名。**

单子上只有"缺什么、谁来接、交了什么"。谁是谁，记在账本里。

**为什么要这样：** 因为你们要的是"**谁产出谁说话**"，不是"**谁资历深谁说话**"。单子上没有人名，这个池子就不会变成"看人下菜碟"的地方。

**★ 还有一个和"元老院"有关的澄清：**

之前讨论的"元老院管准入"，方向其实不对。

> **它管的不该是"谁能进来"，而是"什么东西有人接"。**

因为**进不来人的真正原因不是"坏人太多"，是"没人看得见需求"和"没人信得过对方"**。所以入口要解决的是"匹配"，不是"审批"。

**这也是"不太喜欢元老审核那一套"那个不适感的真正来源——那个机制解决的是一个不存在的问题。**

## 六、账本怎么算（credit 的功能）

### 6.1 credit 是什么

**一句话：它衡量的是"别人从零做出同样的东西，要花多久"。**

**不是"谁资历深"，不是"谁说得漂亮"，是"这件事有多费工夫"。**

**为什么用这个：** 因为它是唯一**不需要任何人拍板、也无法争辩**的标准。花了一小时的东西就是一小时。

### 6.2 谁来估这个时间

**★ 关键设计：不让你自己报工时，让复核的人估。**

| 做法 | 后果 |
|---|---|
| 自己报工时 | **必然虚报**，而且没法查 |
| **复核的人估** | 复核的人反正要读一遍，顺手估；**而且换个复核的人可以交叉校对** |

**这个设计的真正作用是：把"定价权"从做事的人手里，移到了检查的人手里。**

**于是"会讲故事的人给自己加价"这条路被堵死了。** 这正好防住了你们语料里警告过的那件事——信用度可以被"宣发机器"操控。

### 6.3 问题（question）为什么不按成本算

**一个好问题的成本是负的。**

别人不是"从零想出这个问题"，是**根本想不到这个问题**。按成本算，它会被算成接近零，而它恰恰是最稀缺的。

**所以问题按它长出了什么算：**

> **一个问题值多少 = 它引发的所有东西的总分 × 20%**

- 提了没人理 → **0 分**（诚实：它确实没产生价值）
- 提的问题引发了 3 份知识包 → 分那 3 份的 20%

**这条一石二鸟：** 既给了问题一个公平的价格，又**让"问题算不算贡献"这个争论不用吵了——看它长出了什么。**

（只有一个例外：要有上限，不然一个人提一个大问题可以吃一辈子。）

### 6.4 什么能加分，什么不能

| 信号 | 能造假吗 | 作用 |
|---|---|---|
| 复核通过 | **能**（互相盖章） | 只是门槛，**不加分** |
| 开单的人说好用 | **能**（互相捧场） | 只是门槛，**不加分** |
| **被别人引用了几次** | **不能** | **★ 唯一能加分的** |

**为什么引用不能造假：** 因为引用别人是要花成本的——**你得先读懂它才能引用它。没人会为了给别人刷分，去读一个没用的东西。**

### 6.5 有件事必须诚实说：credit 现在什么都换不到

**它换不到钱、换不到算力、换不到权力。**

**所以它现在就是一个记分牌。** 这不是贬低——记分牌有用，它让"谁让池子变大了"看得见。**但给记分牌定精确价格是假装它更严肃，反而会让人去刷它。**

**它真正有含义的那一天，是它开始决定"谁掏服务器钱"的那一天：**

> 服务器一个月 100 块，三个人分。谁上个周期产出多，谁就少摊甚至不摊；谁没产出，谁就多摊。

**而这件事不需要钱就能成立**——你们只要开始分摊那台机器的费用，credit 立刻就有了真实含义。

**★ 于是"不发东西就衰减"和"分摊"自动接上了：** 不产出 → credit 衰减 → 分摊比例上升。

**这是一个自动的、不需要任何人来裁决的机制。** 不用投票、不用审判、不用谈。

**并且它解决了一个很实际的问题：怎么让老人自然让位。** 不是把人赶出去，**是让位置自己空出来。**

## 七、谁来管（管理基础·二）

### 7.1 维护者：可以推快，不能拖慢

**这是唯一一条能防止"一个人说了算"的设计。**

| 维护者**可以**单方面做的 | 维护者**不能**单独做的 |
|---|---|
| 确认交付物 | **关闭一张开着的单** |
| 推进状态 | **推翻已经通过复核的东西** |
| 回复异议 | **改别人该得多少 credit** |

右边那三件事**必须第二个人同意**。

**为什么这么设计：** 因为一个人掌权时最常用、最难防的手段，**不是乱做事，是不回应**。所以配套一条：

> **任何人有异议提出来，维护者必须在 7 天内回应——哪怕回应是"驳回"。不回应，这件事自动升级，交给核心的人一起处理。**

### 7.2 三条铁律

| 铁律 | 意思 |
|---|---|
| **只追加，不删除** | 记错了不是删掉，是**再写一条"我改一下"**。**原记录永远在** |
| **改规则不算改代码** | 规则写在一个文本文件里。**想改规则就追加一条记录**，不用改程序、不用发版 |
| **不能为了让检查通过而放松检查** | 检查卡住了，**只能改事实，不能改检查** |

**第三条是整个系统能不能长期可信的唯一保障。** 因为"放松检查"永远是当下最省事的选项。

### 7.3 机器人：它只是钟，不是手

**它只干一件事：定期把"没人注意的东西"翻出来。**

比如每周报一次：

- 哪个单子快过期了
- 谁的交付堆着没人复核
- 谁提了异议没人回
- **★ 上个周期通过了、但一次都没被引用的东西** ← **这条是它存在的全部理由**
- 哪两张单子看着像重复

**★ 最后那条"通过了但没人用"是最有价值的**，因为：

- 复核通过了 → 说明第二个人看过
- 开单的人确认了 → 说明提出的人满意
- **但没人引用 → 说明它对别人没用**

**三件事同时成立，就是一个信号：我们在生产"自己能验收、别人不需要"的东西。**

**这个信号不会自己冒出来**——因为每个人都在做自己那一环，**没人看整体**。只有机器人会问这句话。

**它绝对不能做的三件事：**

1. **不能改状态**——只能看，只能报告
2. **不能当复核的人**——不能又当运动员又当裁判
3. **不能自动关单**——关单是判断，**"自动关掉"等于把判断藏在程序里，没人看得见**

## 八、现在是什么状态，下一步做什么

### 已经定了的

| 项 | 结论 |
|---|---|
| 形态 | 本地六个文本文件 + git 备份 |
| 防赖账 | 签名 + 串链子 + 周期打标签 |
| 上链 | **不上**（会破坏"内部使用"这个前提） |
| 公告板 | 开单 → 接单 → 交东西 → 验收 |
| 单子上 | **不写人名** |
| credit | 按"别人重做要多久"算，**复核的人估** |
| 问题 | 按它长出什么算，20% |
| 加分 | **只有"被引用"能加分** |
| 维护者 | 能推快、不能拖慢 |
| 机器人 | 只报告，不判断 |

### 还没定的（这些只有你能定）

1. **credit 的具体数值**（复现成本 ÷ 10，这个比例合不合适）
2. **问题的版税比例和上限**（20% / 上限 200？）
3. **衰减速度**（多久减半）
4. **复核权给不给人以外的东西**（我建议第一版只给人）
5. **机器人多久跑一次**

### 下一步该做的，只有一件事

**别搭系统，先跑一张真单子。**

```
1. 你开一张单：说清缺什么 + 怎么算做完了
2. 你自己接
3. 你交东西
4. ★ 找第二个人来复核
```

**这一步验证的只有一件事：第二个人光看"怎么算做完了"这一栏，能不能判。**

- **能判** → 整套东西成立，接着写代码
- **判不了** → 是"怎么算做完了"写得不够清楚，**回去改，不要往下走**

**为什么必须先做这个：** 因为整套账本的可信度**全压在"验收标准清不清楚"这一点上**。这一点不成立，写多少代码都是白写。

## 九、最后：这一切是为了什么

**不是为了建一个社群。**

> **是为了让一个人四个月攒下来的东西，有人看得见、有人用得上、有人接着做。**

**所以判断这个项目活着的标准，只有两个数：**

- **池子里新东西的速度**（还长不长）
- **有多少东西被别人引用了**（有没有用）

**如果三个月没有一张新的申请单，或者一个周期下来成案数是零——那不是需要改制度，是这件事本身跑不通。**

**到那时候，改制度是最没用的反应。**
