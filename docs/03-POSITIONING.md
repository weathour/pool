> 合并自 `12-初心.md`、`14-平台定位.md`、`15-初衷与目标诊断.md`、`11-仓库形式-完全公开.md`、`16-开源镜像.md`（现均已归档到 `docs/archive/`）。
> 五份是同一主题（"这个项目是什么、要做成什么"）在不同轮次的产物，**后面的推翻过前面的**。本文以最终结论为准；被推翻的方案连同推翻理由保留——"为什么不做 X"和"选了什么"同样重要。

## 一、一句话

> **把自己攒下的资料、经验、和处理资料的方法放进一个公共的地方，并且给"想一起做事的人"一个不用互相认识也能对接的入口。**

两个半句缺一不可：只有仓库 → 别人看完就走，**没人留下**；只有平台 → 热闹但没东西，**变成普通群**。落到形式 = **一个公开的 git 仓库 + 四份 JSONL + 一个校验器**；落到产出物 = **"可验证知识单元"的生产单元**——别人卖答案，它卖"这个答案什么情况下是错的"。

- **仓库层**（智库：提问/回答/评价 · 硬件基建：服务器、域名、机器人、资料处理 · 资料保存与处理：语料、卡片、档案、账本）= 公共品 / 公摊资源 / 存量：答案不因被多人看而减少、成本已发生（多一个人用不增加成本）、越用越值钱；**协作层**（招募板：贴公告、互相联系 + 结算）= 匹配市场：要定价、要成交、要清算。

**"协作申请"四个字是钥匙：发起单位不是"人"，是"需求"和"提议"。** 链条是 `有人提出需要什么 → 其他人看到 → 评价、建议、或加入 → 形成协作`——**这条链里没有"审批者"**：没有机构决定"你能不能来"，只有"这个需求/提议有没有人接"。

## 二、它不是什么 / 是什么
| 不是 | 是 |
|---|---|
| 一个社群 / 一个容器 | 一个知识项目；**"社群"是这个目标的容器，不是目标本身** |
| 一个工具站 | 一条能产出可核验结论的流水线 |
| 一个哲学知识库 | **一条能让人和模型协作产出可核验结论的流水线**——语料受版权约束，流水线不受 |
| 内容转售生意 | 别卖内容，卖那条能产出内容并留下证据链的流水线 |
| 邀请制俱乐部 | 完全公开的仓库，**"成员"这个概念已经消失**（见 4.2） |
| 靠"去中心化"标榜的组织 | 多中心分权 / 席位轮换 / 按物不论人（见 4.4） |

**三层目标，从最可靠到最不可靠**（事实层与资产证据见 5.1）：① **事实层（可断定）**——把私人整理的、不可验证的哲学知识，变成公共的、可验证的知识资产（*一个想传播观点的人不会这么干，一个想让观点被检验的人才会*）；② **动机层（高置信推断）**——验证"这套方法能不能真的产出站得住的东西"，而不只是"这套内容对不对"，核心命题是**人和模型的协作，在足够严格的证据纪律下，能产出比人单独或模型单独都更可靠的知识**；③ **结构层（低置信，可被直接否掉）**——"社区"这个词可能是借来的：仓库里跑得最顺的是**纪律**和**会计**，**没有一丝"集体生活"的痕迹**（没有讨论、没有投票记录、没有成员名单、没有会议纪要，四个月里只有一个人在做决定）；群聊里最热的是 credit 记账与"谁能进来"（会计与资格问题），**被跳过的是退出、资产归谁、争议怎么裁、失败了怎么办**。

**产出物定位的三个候选：**

| 候选 | 定位 | 要害 |
|---|---|---|
| **P-A 知识生产合作社（推荐为主）** | 把"人和模型的协作产出"变成**可核验、可计价、可交易的知识单元** | **组织形态跟着产出物走，而不是反过来**；没有社区、没有会员、没有元老院，只有"谁在这期里产出了被验证的东西" |
| P-B 知识工场（外包式） | 接单生产可核验知识单元的乙方，人力和模型都是可替换的产能 | credit = 纯计件工资、人机同价、谁产出谁拿；现金流直接、无需社区运营，但**会退化成内容农场**；单独做没有护城河，只能作为 P-A 接单时的执行形态 |
| P-C 训练/认证机构 | 教人怎么和模型协作做可核验研究 | 卖的是能力转移，边际成本近零；中文市场付费意愿真实、语料天然是教材；但依赖个人品牌、启动慢、**同样踩版权**（教材不能直接用 B 站转写） |

**推荐 P-A 为主 + P-C 做第一批现金流**：P-A 的产出物（知识包）正好是 P-C 的教材，P-C 的学员正好是 P-A 的产能来源——同一条流水线，两个出口。

## 三、要解决的问题

**稀缺的不是知识，不是算力，不是答案：是"陌生人之间的信任"。** 仓库解决一半——**让一个人说过的话变成可查的**；协作申请平台解决另一半——**让两个人不用先认识就能开始合作**。**邀请制是错的方向**：它只在已有熟人网络里分配信任，不生产新的信任。

**为什么以前做不到、现在能做了：** 一个人做仓库很自然（260 个提交就是证明）；但"仓库 + 匹配"一起做，历史上只有大组织干得成——**匹配成本（介绍、撮合、定约、验证、催账、处理赖账）随人数指数上升**。小群体做这个，结果一定二选一：变成死资料库，或变成活的聊天群加一个没人看的资料夹。**agent 第一次改了这个成本结构**（撮合、初筛、验证、记录、催办现在可以自动化），**所以这是 2026 年的对话，不是 2016 年的。**

**两层必须用不同性质的账，混了就两层都废。** 语料里正好有这个区分：*"这是纲领，那么最左边是习俗再往那边退就本能了……最往下面就是交易了，交易有对价的行动或者有偿行动。"* —— 庶政学预备工作（1），`library/manifests/shuzheng-practice-agent-reviewed-evidence.jsonl:2`（`analysis_status: V`，仅作有界释义）。纵轴就是"交易（有偿 / 有对价）↔ 无对价行动"，两层正好落在两端：

- 行动性质：**无对价**（我回答你，不图你什么）↔ **有对价**（我加入你的项目，要拿回报）；能不能定价：**不能**（定不了"一个好回答值多少钱"）↔ **必须**（不定价就没人来）；记录方式：按贡献记账（reputation）↔ 按成交结算（payment）。
- 失败形态：**定价了 → 提问变下单，没人愿意答**（仓库层）↔ **只记账 → 变互相吹捧，匹配市场死掉**（协作层）。
- 记什么：你让公共池变大了多少（**不可转让、不可兑换、只增不减**；用于席位、声誉、话语权重）↔ 一次协作里谁该拿多少（**可清算、可对价、有债权债务**；用于真金白银的分配）；出处：前者 = v3 的 credit（双层衰减那套；算法与计量见 `02-credit.md`），后者 **v3 完全没设计，是真空白**。
- **结论：credit 必须分两种，不能是一种。招募板没有结算，就只是个留言板。**"成员"这个统一身份也是多余的：有的是**提问者、供给者、接单者、复核者**——一个人可以同时是四个，但不必先成为"成员"。
- **问题诊断：你们不缺组织设计，缺的是"这个东西被外面的人看见并认了"。** 组织设计是这个问题的**拖延方式**——它让人感觉在推进，而实际上库没有变大。语料对自己最狠的一句判词就是这个意思：**organization for practice by itself**（`library/themes/governance-law-bureaucracy/governance-law-bureaucracy-synthesis.md:15`）。**搭组织不是实践，让库变大才是。**

## 四、五个"曾被推翻的定位"

### 4.1 定位一："纯知识生产项目，社群只是容器"（`15`）→ 被 `12` 推翻
上一版读法：重心放在"260 个提交、可核验、证明方法论"上，于是得出"这是一个知识生产项目，社群只是容器"。**它抓住了资产，但漏了一半：仓库里的东西是用来被用的，而"被用"需要一个入口。**

- 资料：抓住了（语料、细读卡、主题档案）→ 它是仓库的**存货**；**经验：完全漏了** → 它是仓库里**最不可复制**的部分；**服务：当成"功能清单"** → 它其实**就是那个入口**。
- **"经验"漏得最厉害**：真正独有、别人抄不走的，不是哲学内容（那是 B 站讲者的），也不是工具代码（那是可复制的），而是——**怎么让模型产出可核验结论的那套操作经验、194 个审查条目背后的判断标准、27,500 行工具踩过的坑、哪些做法是死路及为什么**。**"资料"是可以买的，"经验"不能。**
- **群聊里说出来的目标是"建一个社群"**（公摊成本做基建、基建成果共享；服务 = 智库 / 硬件基建 / 招募板；义务 = 不捣乱、平摊、出力；成员 = 邀请制、2 元老同意；谁来设计平台和架构然后租服务器搞）。**但唯一暴露动机的一句是"后续我肯定是要再拉人的"**——说出来的目标是**容器**，实际发生的动作是**内容**："想让自己做了四个月的东西有人接着做、有人认"。**把容器当成目标是危险的，因为它会让人以为搭好了架子就等于做成了事。**
- **推翻后的结论：它同时是一个仓库和一个协作申请平台。** 顺带修正的还有顺序（`14` §0）：必须是 **产出物 → 平台定位 → 治理 → credit 计量**，v2 的顺序是反的——因为**治理形式必须匹配产出物**：credit 若定成"对公摊资源的提取权"，就预设了产出物是内部自用的；产出物要对外卖，credit 就必须能对应**收入分配**，否则贡献者拿不到回报，第一批人就会走。

### 4.2 定位二："元老院 + 邀请制 + 2 元老同意"（群聊原话 / v1-v3）→ 推翻
原主张：成员 = 邀请制、2 元老同意；元老院管准入与清退。**结论：管错了对象**——元老院管"谁能进来"，实际机制管的是"什么东西有人接"，**一个管资格，一个管匹配**；准入是治"匹配失败"的错药，而匹配失败的原因是"没人看得见需求"和"没人信得过对方"，不是"坏人太多"（`12`）。**需要的是"你的知识包过不过复核"，不是"准入"这个概念**（`15`）：**人不是被批准进来的，是被产出带进来的。**

完全公开之后"成员"概念随之消失——没有名单要维护、没有准入要审批，只剩 `members.jsonl` → **`keyring.jsonl`（公钥目录，不是成员名单）**：`{"pubkey":"ed25519:...", "handle":"雁", "since":"2026-09-16", "status":"active|retired"}`。名单 = 有边界、要审批、进不去就用不了；目录 = **没有边界，任何人加一条自己的记录就能开始干活**；**"移除"也不需要**——加一条 `status: retired` 就行，**历史记录里的签名永远有效，因为它当时确实是他签的**。

> **完整论证在 [`05-GOVERNANCE.md` 第四节](05-GOVERNANCE.md)**（普查结论："元老院"在 curated 层零命中，全库仅 6 次且全在 `corpus/bilibili-asr/` 原始 ASR，如 `BV1TW42197z3__...txt:107`；同类的"贵族共和""制宪""建党""秘密结社"也全部只在 ASR）。定位层面只剩一条配套改动：把"招募成员"改成"让产出可见"——**"拉人最有效的办法不是元老院投票，是把仓库挂出去，让方法本身成为筛子"**（`15`）；完全公开之后，这句话变成了字面意思（`11` §4.1）。

### 4.3 定位三："分层公开"（v3 时期主张：public 层 + private 层，完整论证见 `16`）→ 被 `11` 推翻：完全公开
**原方案的论证：** 前几轮所有的法律简洁性都建立在"**内部使用** → 不需要备案、不需要处理版权、不需要注册主体"这一句上；开源之后，这一句直接失效。

| 之前说"不是问题"的 | 开源后的状态 |
|---|---|
| B 站转写原文可以进池子 | ❌ **不能公开分发** |
| 不需要 ICP 备案 | ⚠️ 若挂在自己域名下对外可访问，**又回到备案问题** |
| 不需要法律主体 | ⚠️ 一旦有公开的义务与回报约定，性质就变了 |

于是提出分层公开：`public/` = requests.jsonl（公告板，本来就设计成不含人名）· deliverables.jsonl（交付物，本来就不含人名）· cycles.jsonl（周期结算 + Merkle root）· 结论与锚点 · tools/ docs/ policies.jsonl；`private/` = members.jsonl（成员身份）· credits.jsonl（账本，含人名）· maintainer-log.jsonl（维护者操作）· corpus 原文（B 站转写，只在本机）。

- **★ 这个分层几乎是免费的**：前面定"单子上不写人名"的时候，public 层就已经天然准备好了——当时那个决定是为了"谁产出谁说话"，现在顺便解决了开源合规问题，**是那一轮最值钱的副产品**；**它也不削弱可验证性**：public 层的 `cycles.jsonl` 带着每期的 **Merkle root**，而那个 root 由**全部六份文件**算出，任何人拿到 public 层都能验证"这一期的完整状态是那个哈希"，只是看不到 private 层的内容。这叫**"可验证但不公开"**。
- **credit 里有人名，两个选择**：A. credit 不公开，只公开每期的**汇总结算**（总数、占比分布），代价是外部无法核验单条 credit——**当时建议 A**；B. 公开但用假名，代价是假名在长期行为下**会被推断出身份**（谁写的东西风格很明显）。
- **谁说了算**：不能既说"人人可克隆"、又说"以我这份为准"，所以**不设权威，设证明**——每期结算由维护者发布一个**签名的 Merkle root**，镜像持有者验证自己的副本算出来的 root 对不对得上：对得上即可信，对不上就是被改过（或结算后又被追加了东西）。**信任的对象从"仓库"变成了"那个签名的 root"**——谁的仓库都可以是权威，只要 root 对得上；维护者能改自己的副本，但所有镜像的 root 会对不上。
- **写权限分三层**：代码 / 文档 / 规则 = 任何人（提 PR，维护者合并）；`data/` 文件 = **单写者**（或少数几个签名者），每条记录必须有有效签名，**未签名 / 签名无效的追加直接判失败**；镜像 = 任何人，克隆即镜像，无需许可。**代码是开放的，数据是受控的，验证是开放的**——而"数据受控"不需要任何权限系统，**签名本身就是权限**。

**推翻：新前提是"完全公开，不分层，内部没有版权"。**

| 分层方案里的东西 | 完全公开之后 |
|---|---|
| private 层（身份 + 账本 + 原文） | **取消**。没有"内部资产"和"已发布"的区别，只有"在 main 上"和"不在 main 上" |
| 六份文件 | **降到四份**：`requests` / `deliverables` / `credits` / `keyring` |
| `cycles.jsonl` + 每期 Merkle root | **删除**，周期结算改用**签名 git tag**（commit 的 SHA 覆盖整棵树）：`git tag -s cycle-2026-Q4 -m "本周期 12 张单，成案 5 件，打回 3 件"` + `git push --tags`——**一条命令，替代一整个文件** |
| `members.jsonl` / `maintainer-log.jsonl` | 前者 → `keyring.jsonl`（见 4.2）；后者简化成 `MAINTAINERS.md` + git log，不需要独立文件 |
| `prev` 字段 | **去掉**（git 的 commit 链就是那条链；`prev` 是为"没有 git 的世界"设计的。唯一保它的理由是数据脱离 git 单独存在时仍可自验，但完全公开、随时能 clone，这个理由不成立） |
| credit 只公开汇总 | 失去载体（不再有私有层放明细） |

**为什么"分层"不行（`11` 只给了结论和简化结果，论证补在这里）：** ① **分层需要一个"内 / 外"边界，而这个边界要靠成员名单 + 准入审批 + "谁能读 private 层"的权限系统——正好是 4.2 刚刚取消掉的东西**（名单 → 公钥目录，准入 → 知识包复核）。分层会把"资格"重新请回来，这是与定位直接冲突的代价，不是实现细节。② **git 里没有"private 目录"这种东西**：sparse checkout 只影响工作区、不影响对象库，clone 出去的东西收不回来——所以 private 层在 git 里实际等于"不发布"，那份数据一份镜像保证都没有。③ **分层方案最值钱的那句话自己站不住**：`16` 说 public 层的 `cycles.jsonl` 带着 Merkle root、而 root 由**全部六份**文件算出，"任何人拿到 public 层，都能验证这一期的完整状态是那个哈希"——**缺三份文件的人算不出这个 root**，外部能验证的只是"这个哈希字符串没被改"，不是"这一期状态确实是这个哈希"。替代品反而更强：**签名 git tag 的 commit SHA 覆盖整棵树，任何人 clone 后都能自己重算**，不需要任何私有层。

**credit 明细是否公开：公开，而且已经是事实。** 分层方案里"只公开每期汇总"的唯一理由是"private 层还在"；private 层取消后，`data/credits.jsonl` 就和另外三份一样躺在 main 上（clone 即得，含 handle 与金额）。代价是外部能看见每个人的每一笔记账——**这正是要的**：账本是这套东西里唯一能自证的部分，把它藏起来，公开仓库就只剩一个空壳。

**但有一件事必须摆在明处（`11` §0）：仓库是公开的，等于 363 篇 B 站转写是"重新发布"，而不只是"自己看"。** 这不影响自己用，也不影响开发，**但它是一个已经做出的选择，不是没发生的事**。雁雁 09-16 说过"好像人多了得备案……那也是小事，又不造反"——逻辑相同：**按自己的判断承担，但要让这个选择是"知情的"。**

### 4.4 定位四："去中心化"（v1/v2 的定位词）→ 显式撤回

### 5.2 镜像与防篡改
**最重要的理解转变：防篡改 ≠ 防复制。**

- 防复制（传统"防篡改"的意思）：目标是别人不能改**我的**副本；手段是权限、加密、服务器控制；结果是闭源、中心化。**防篡改（真正要的）：目标是"别人改了他自己的副本、能被立刻发现"；手段是签名 + 哈希链；结果是开源、可克隆、可镜像。**
- 不可能阻止别人克隆后改自己的那份（技术上不存在）；能做到的是**任何被改过的副本一眼就能看出来**：**签名** → 改了就验不过；**哈希链** → 改一条，后面全对不上。**开源和防篡改不矛盾，它们是同一件事的两面——越多人克隆，越多人手里有原始副本，改账越难。**
- **git 本身就是协议，不需要发明**：哈希链（`prev` 串上一条）→ **commit 链**（每个 commit 的 SHA 覆盖整棵树的当前状态）；不可篡改的历史 → git 历史 + `git fsck`；多人持有的独立副本 → **每次 clone 都是完整镜像**；分发与同步 → `clone` / `fetch` / `push`；周期快照 → **签名 tag**；提案与评审 → **issue / PR / review**；谁改了什么 → `git blame` / `git log`。**★ 结论：不需要发明协议，需要的是一个仓库 + 一份贡献指南。**
- **但 git 做不到：证明"是谁"写的、防抵赖、防止冒充**——原因是 git 的 commit author 是**自己填的字符串**，随便写成谁都行；而且**改历史只需 `git commit --amend` + `push -f`**（在允许强推的仓库里）。所以签名不是可选项：**git 负责"没被改"，签名负责"是谁写的"——两者加起来，才是"防篡改"。**
- **镜像落地（零成本）**：① 主仓库放一个公开平台（GitHub / Gitee / 自建 Gitea）；② 任何人在任何地方 `git clone --mirror` 得到完整副本；③ 每期结算时维护者打一个**签名 tag** 并 push；④ 镜像持有者 `git fetch` 后验证签名是否有效、内容是否对得上。**风险与对策**：GitHub 国内访问不稳 → 同时推 Gitee 或自建 Gitea（**多镜像本身就是目的，不是妥协**）；平台封号 / 删库 → **镜像越多越安全**（这是开源的核心优势）；只有一个镜像 → **那就不是镜像**，至少 2～3 个独立位置。**★ "多人持有副本"真正的价值**：不是技术上的不可改性，**而是任何篡改都会在多个独立副本之间产生可见的不一致**。
- **单写者的地位更关键了**："谁签的"变成公开可见的事实——好处是**谁动过账，链上一目了然**；风险是**单写者成了显眼的攻击目标**（社会工程、胁迫、私钥窃取）。对策按重要性：① 私钥**离线保管**（不放在联网机器上）；② 签名可以离线做（算出 root → 拷到离线机器签 → 拷回来）；③ **多签名**（超过某个规模后，关键操作要求 2 个签名）；④ **镜像持有者互相监督**（任何一份副本对不上 root，就是事件）。
- **威胁模型从"保密"换成了"完整性"**：之前"谁能看 / 谁能用 / 谁能镜像"= 成员 / 成员 / 不能，权威在"我的机器"，最大风险是**数据被看**；现在 = **任何人 / 任何人（按开源许可）/ 任何人**，权威**在签名和 root 里，不在任何机器里**，最大风险是**数据被改**（而"被看"已经接受了）。**机密性彻底不是需求了，完整性和真实性变成了全部。** 公开层要给开源许可（否则镜像没有法律依据）：建议 **MIT 或 CC-BY-SA**，看你们对"署名"和"传染性"的取舍。**账本的哈希链 / 双签 / Merkle root 锚定见 [`02-credit.md`](02-credit.md)**（`16` §4.2 当时留了三个锚定档位：签名 git tag 零成本 / 免费 RFC 3161 时间戳服务 / 公共链锚定 32 字节 root，¥0～40/年；最终结论与理由以 `02-credit.md` 为准）；这里只留一条定位结论：**可核验性从"信任问题"变成了"技术必需"**——你没法用"相信我"来管理一个模型账户。

### 5.3 可替换性：模型成员制 + 席位轮换
**模型进账本，作为受限主体**（已经有 agent 持有 API key、有预算上限、可以自主调用的部署形态——**模型已经是经济活动的参与者，只是没有被当作成员**）：

- **L0 算力节点**：无自主权，只提供算力，账本记它的贡献归属其主人；**L1 工作模型**：可提案（生成知识包草稿），**不能自我确认 credit**；**L2 审查模型**：可复核**他人**（人或模型）产出的知识包，**必须与产出者不同主体**；**L3 议事模型**：可对定位/口径提出异议并强制挂号（触发人工复核）。
- **三条硬规则：** ① **任何 credit 的最终确认必须有人类签名**——模型可以赚 credit、可以消耗 credit、可以用 credit 调用别的模型，但**确认权在人手里**，这是防自循环的最后一道闸；② **审查模型不能审查自己的产出，也不能审查同源模型的产出**（防串谋，参考仓库的 reviewer-pass independence 校验）；③ **模型产出的知识包必须标注模型 ID 与版本**，因为模型升级后旧结论可能不再成立——写进 schema，不靠记性。
- **为什么这算激进而不是噱头：** 现在所有人的 agent 都是**成本项**（消耗 token）；这里 agent 是**能积累 credit 的产能**——一个 L1 模型通过产出知识包积累 credit，用这些 credit 调用更强的模型来复核自己的产出，这是一条自动的质量上升通道，不需要人审批每一步。**"模型管理"因此从一个成本问题变成一个会计问题**：每个模型是一个有余额、有产出、有审查记录的账户。**人的可替换性走 P-B 那条线**：人力和模型都是可替换的产能，credit 按计件、人机同价、谁产出谁拿——但它只作为 P-A 接单时的执行形态（单独做会退化成内容农场，见第二节）。
- **成本结构是顺风：** 生产级 LLM 系统最有效的省钱手段不是砍功能，是**按任务难度路由到不同模型**——抽取、分类、格式化、引用定位用便宜模型，只把真正难的推理送到前沿模型；流水线里有大量机械劳动（按 row 定位、抽引文、算字符范围、跑 schema 校验），便宜模型完全够用。所以**账本必须记录每次调用用的哪个模型**——不是为了审计，是因为**"用便宜模型能否验证"决定了流水线的单位成本**。小模型价格还在快速下降，成本结构会随时间自动改善，而纯人工竞品不会。
- **席位按期重排 = 位置可以换人**：每期末按该功能的活跃 credit 重排席次，不设终身席位；公钥目录用 `status: retired` 记人走了，签名历史照旧有效。

### 5.4 落地顺序：先卖，后建
```
第 0 步  定死知识包 schema（六件：4 件已在 content 里，review 已是独立记录，provenance 待加）。零成本，就是一份 JSON 模板
第 1 步  ★ 用现有语料手工做出 3 份知识包，找 2 个外人（非成员）独立复核
           —— 验证"复核者能不能只靠 anchors 复现结论"；复现不了 → schema 有问题 → 回去改，不要往下走
第 2 步  ★ 拿这 3 份知识包去问 5 个潜在客户：这东西你愿意付钱吗，付多少 → 回答决定 P-A / P-B / P-C 选哪个
第 3 步  只有当第 2 步有 ≥1 个真实报价，才建基建
第 4 步  建账本（两个 JSONL），credit 用双层衰减制，三院席次按活跃 credit
第 5 步  模型账户接入（L1 → L2 → L3 逐级放开，每级跑 4 周看有没有失控）；第 6 步  每期重排席次（首个周期建议 90 天）
```

**第 1、2 步是关键改动**（v2 说"先搭账本再搭平台"，v3 反过来）：schema 能不能被外人复现，是**唯一真正需要提前验证的技术风险**；有没有人买，是**唯一真正需要提前验证的商业风险**——两件事**加起来成本是零**（不用服务器、不用域名、不用写代码）。**都过了，剩下的都是执行问题；没过，你省下了全部基建投入和全部治理设计的力气。**

- **完全公开带来的循环：** 有人开 issue（= 开单）→ 有人提 PR（= 交东西）→ CI 跑 `validate`（= 形式检查：签名有效吗？验收标准写了吗？）→ 维护者合并（= 验收）→ **合并进 main = 入库 + 上账，一次完成** → README 第一屏重新生成，**不需要第三个动作**（★ **这一环还没做**：现在的第一屏是手写的，`tools/build-site` 只生成静态站）。
- **仓库实际长这样（截至 2026-09，与上面的目标形态对照看）：** `README.md`（第一屏 = 当前公告板，**手写**）· `CONTRIBUTING.md` / `CONTRIBUTORS.md` / `别人怎么用.md` · `MAINTAINERS.md` + `CODEOWNERS` · `data/`（★ 四份 JSONL，唯一的真相）· `policies.jsonl`（11 条规则）· `tools/`（9 个：`sign` / `validate` / `status` / `cycle` / `verify-meta` / `fixlinks` / `resolve` / `build-site` / `gitea-home-data`）· `tests/` + `selftest.py`（101 项）· `docs/`。**`library/`（资料）不在这个仓库里**——语料在另一个仓库，这里只放引用；**`experience/`（★ 经验）还没建**，而它正是 4.1 里"漏得最厉害"的那一项。
- **完全公开反而让"对接"更难了，不是更容易**——私人池子里三个人，谁需要什么一眼看得到；公开仓库里没人知道该看哪儿，这是"公共资源困境"的镜像版。所以入口有三个答案：① **README.md 第一屏 = 当前公告板**（正在招人接的单 / 刚交付的东西 / 刚被采纳的结论），**必须自动生成、不能手写——手写的一定会过期**；② **每个结论都带着"它还缺什么"**——结论里的"反证条件""停止条件"字段，本身就是"这里有个没解决的问题"的钩子；③ **经验单独有一个地方**（不是"我做了什么"，是"我踩过什么坑、为什么当时那样决定"）——这一层现在藏在 `reviews/` 里，外部人看不到，而它恰恰是外部人最需要、也最能说明"这里值不值得来"的东西。**★ 第 ③ 条是目前最被忽略的一块**：194 个审查条目、70 对候选/决定是四个月的真实判断过程，它的价值不在于"结论对不对"，在于**"一个人是怎么在没把握的时候做决定的"**。**资料在 `library/`（已经很好），经验要单独有一个明确的位置。**
- **入库标准也跟着变了：** 内部池子时 = "对我们有用"；公开仓库 = **"对陌生人有用"**，后者严得多——但它正好是"可验证"的自然结果：能不能看懂（锚点够不够）？能不能自己判（反证条件写没写）？能不能接着做（还缺什么写没写）？所以入库标准简化成一句：**一份东西能不能进池子，看一个陌生人照着它，能不能自己往下走**——这句话**同时是入库标准、是验收标准、也是公开的说明书**。
- **机器人只剩一件事：** 校验链、签名归 CI（每次 PR 都跑）；过期单、堆积的复核、**通过了但没人用的东西**、可能重复的单，CI 做不到（它只在有 PR 时触发）→ 归机器人，cron 一周一次。**"通过了但没人用"这条告警公开之后更重要**——因为"自己人能验收、外部人不需要"是一个会被公开看见的事实。

## 六、边界与风险

### 6.1 法律：这是一个中介，不是一个资料盘
米波大神在群里问过"**你这会不会违法哦**"，雁雁答"自己服务器自己用，违鸡巴法……好像人多了得备案……那也是小事"。**按最终读法，这个问题比当时的判断重得多**："**资料仓库**"确实很简单——自己用、备案、没问题；但"**协作申请平台**"不一样：一旦这个池子开始持续地**发布需求、撮合他人、约定回报、分账结算**，它在功能上就已经是一个**中介**了，而中介有它自己的法律形态要求和风险，跟"自己用服务器"不是一回事。**在动任何代码和服务器之前，"平台在法律上是什么"这个问题必须先有答案。** 米波那句不是外行话，是这个设计的第一个硬约束，而且它出现在第一轮讨论里、被当成"小事"跳过了。**版权是硬约束，不是选项**：对外交付的知识包**必须**不含 B 站转写原文，只能含自己的结论 + 锚点引用；语料可以内部用、可以研究，**不能直接商业化转售**。完全公开之后 363 篇转写是"重新发布"（见 4.3），ICP 备案与法律主体的问题也随之回来。

### 6.2 语料对"把语料变成现实组织方案"的系统性拒斥
必须遵守的边界：**不得从"结构矛盾"直接跳到"政策或治疗处方"**（`library/protocols/relational-subjectivation-praxis-protocol.md:208`）；**不得把本卡当作现实组织手册、政治行动处方**，证据等级为 IE0，不提供现实样本、有效性数据或反馈记录（`library/close-reading/processes/process-0333-strategic-organization.md:14`、`:35`）；**不是新 theme、平行分析协议、事实权威或行动处方来源**（`library/courses/shuzheng-practice/README.md:3`）；**不得据此评价真实组织、保证管理效果、提供人事方案或陈述法律事实**（`governance-law-bureaucracy-external-v-evidence.jsonl:1` 的 `scope_boundary`）。**所以：语料只作诊断工具（指出会怎么死），设计部分全部标注为推断；锚点用于"批判"，不用于"论证设计正确"。** 唯一一处语料对同类方案的正面许可，是讲者在给出"不要加以实践"的禁令后单独划出的尺度例外：*"办个公司，你可以这样搞，搞个小公司，自己搞一个小厂，或者说一个小作坊，自己搞点文创。"*（row 288 `corpus/clean-markdown/4_实践/4-1_复习/4-1-2_灌输/4-1-2-4_现实的本体论化/0288_..._p7468.md:144`）——**它把"小公司 / 小厂 / 小作坊 / 文创"明确划为例外，现在这个规模正好在这个例外里，但也仅在这个规模里；一旦做大，就回到"注定失败"那条线上。这是应该预先知道并接受的事。**

### 6.3 形式必须与内容一致（最强的一击）
*"共济会它是一个一小撮、极小一撮金融资本寡头组织起来的，这是它的形式……那么共济会的内容是什么呢？内容我们看它的章程，它的章程是要最大可能让所有人沐浴在理性的光辉下……你会发现，它的形式、它的组织模式是背叛它的内容的。……**所以真理是站在它的形式上的，而不是站在它这个第一人称的内容的，它的第一人称信条。**……**这个就是虚伪。**"* —— row 83 `library/close-reading/processes/process-0083-capitalism-imperialism-global-capital.md:16` + `corpus/clean-markdown/1_实在论/.../0083_..._p1863.md:56`

**判词：** 如果 charter 写"开放、平等、成果共享"，而实际形式是"三个人掌准入 + 邀请制"，**外部和历史会按形式判你们，不按信条判**——共济会这个例子的判词只有"虚伪"两个字。三种组合：三人创始 + 邀请制 + 一个人拍板 ↔ "三人创始的邀请制工作室"（**可活**，并引 row 287 那条中心化命令为自己辩护）；准入按知识包验证 + 席次按期重排 ↔ "成果共享、按产出论"（**推荐这一行**）；三人说了算 + 对外称开放 ↔ "开放社区"（❌ 判词：虚伪，**唯一确定活不下去的**）。**最大的风险不是技术，是形式与内容不一致——要么把形式改成配得上信条，要么把信条改成实话。**

### 6.4 制度化必然腐化（无解张力，不是 bug）
*"而且历史在通过人、通过理论家这个人来进行的本体论化的这些努力，就是制度化或者科层化的这些努力的**注定失败**……把乌托邦现实化的这种努力是**注定 dome to fail**……它**一定会形式主义化，一定会教条化**"*（row 288 `corpus/raw-markdown/4_实践/4-1_复习/4-1-2_灌输/4-1-2-4_现实的本体论化/0288_..._p7468.md:380–389`）；*"4-1-3 一定会抵达这里，因为这里制度化，**制度化过度人会变蠢，就这么简单。人会变成教条主义、官僚主义、形式主义，他后面会很快僵化。**"*（`corpus/clean-markdown/4_实践/4-1_复习/4-1-3_历史的哲学化/0289_4-1-3_历史的哲学化_p7483.md:12`）；*"它一定会产生我们说官僚化的倾向，或者 whatever 那一种固化的、凝结的倾向，**这是不可避免的。**"*（`corpus/clean-markdown/4_实践/4-2_复习/4-2-2_L主义/0306_4-2-2_L主义_p7737.md:29`）。**但同一段又说：不制度化就没有力量。所以这个张力是无解的**——语料把它当结构性预言而不是建议，而且用了三次"一定""不可避免"。**准确的说法是：衰减制、日落、形式诚实都只是减速器，把腐化从 12 个月推到 24 个月，不是解药。** 别指望它不存在，只要指望它慢一点、并且能在它发生时看得见——**这也是为什么账本比章程重要：章程是被腐化的对象，账本是腐化的记录。**

### 6.5 三个具体的死法，和语料自己给的两个解药
| 死法 | 症状 / 锚点 |
|---|---|
| **(a) 组织被误当成实践本身** | 花三个月搭账本系统、设计三院制、写 charter，一份知识包都没卖出去，但感觉"我们在建设"（`governance-law-bureaucracy-synthesis.md:15`，见第三节） |
| **(b) 理想被等级化利用**（对"共同纲领 + credit"的头号警告） | 上层以指导成员接近理想为由获取世俗回报，使本应作为目的的理想在组织运行中退居为招募与收益分配的工具——`library/manifests/shuzheng-practice-agent-reviewed-evidence.jsonl:16`（V 级，对应"康德式实践→传销"一讲）。症状：credit 从"贡献计量"滑成"等级化汲取的正当化工具"。**这是最阴的一种死法，因为每一步都可以被解释成合理的** |
| **(c) 高压监督 → 抱团互黑** | 上层以选择性惩罚维持可预测威慑，下层为分散风险而结盟并互留不利材料，共同违规遂可能成为防御性合作的纽带——`library/manifests/shuzheng-practice-agent-reviewed-evidence.jsonl:20`（V 级，斯大林式一讲） |

**解药一（针对 c，语料自己写的）**：同一条记录的 counterevidence 写着——*"若存在**透明申诉、独立审查或低成本退出机制**足以打断“监督—抱团—互黑”链条，则该候选应被证伪。"*（`reviews/shuzheng-practice-evidence-candidates-20260815.jsonl:20`）**所以这三样不是可选项：透明申诉、独立审查、低成本退出**——对应到设计里：独立审查 = "复核者必须不同主体"；低成本退出 = credit 双层衰减（退出成本 = 不再产出，无任何手续）。

**解药二（退出权）：语料内部直接对立，必须并置**——支持退出：*"如果你彻底地、绝对地、完整地为人类的共同事业负责努力的话，**你是有这个权利的，就这个游戏你可以退了**"*（`0304_..._p7712.md:146`，紧接着"仅是有这个权利，不代表应该这样做"）、*"**保留最基本的一个就是可以开仓退出**"*（`0347_..._p8669.md:92`）；反对退出：*"甚至是要强行要让他们进来……**你想完全在野、完全逃开，不可能，不允许这样做。**……**你想退出都不行，你必须上我们这个船**"*（`0324_..._p8160.md:57`）。**选择支持退出权**，三条理由：① 反对退出的那一段的语境是"你不能逃避你已造成的社会后果"，针对的是"拍屁股走人不负责"，**它要的是结账，不是留置**；② 语料自己在讲"监督 → 抱团互黑"时给出的解药第一条就是**低成本退出**；③ **一个允许退出的组织，比一个不允许退出的组织更能承受形式/内容的对齐检验**。**硬设计约束：退出成本必须与"已造成的后果"挂钩，而不是零成本**——credit 可以带走结算，知识包留在公共池，未结清的分摊义务要补。**这一条不定，衰减制的正当性就悬着**——衰减制本质上是"用时间代替清退程序"，它预设了人本来就可以走。

### 6.6 复核机制会被绕过（针对复核与双签）
*"让他们 a b c 用 a'、b'、c' 人工智能来**代为他们骗过那个伦理审查委员会和爱欲豁免委员会的监管**"*（`corpus/clean-markdown/4_实践/4-4_复习课/4-4-1_计划良好的人性生活方式/4-4-1-4_醒来/0348_4-4-1-4_醒来_p8696.md:9`）——**这个失败模式就是"用 AI 代理绕过审查"，而在设计里模型本身就是成员，所以它不是比喻，是可预见的攻击路径。** 同一条线上还有：*"它有一个**必然的背景性的操作机制**或者一个控制机制……然后又有一个**偶然的**，它是通过这里面共同体成员的**一些意识表示，或者他们的人与人之间的斗争关系所设立出来的，往往是道德委员会或者说是伦理委员会。**"*（`corpus/clean-markdown/4_实践/4-4_不可能的乌托邦/0342_4-4_不可能的乌托邦_p8560.md:48`）——**含义：委员会同时是"制度必然产物"和"斗争偶然产物"，别指望一个委员会只有功能、没有派系。** **对策（推断，语料没给）**：**复核者的选择必须随机抽签，不能由被复核者挑选**（否则必然出现"找同伙复核"）；**同一模型家族不得互审**（防 a' 骗过 a 那条路径）；**每期公开"谁复核了谁"的全图**，让串谋在图上可见（这是唯一不需要人做判断的审计）；承认这套机制自己也会被绕过，**所以审计的重点不是"防住"，是"绕过后能被看见"**。

**三组必须并置的语料冲突（不许只引一边）**：① 中心化 vs 分权（见 4.4）；② 退出权（见 6.5）；③ "制度化必然腐化" vs "不制度化就没有力量"（见 6.4）。**任何设计如果只引对自己有利的一边，就是在自欺。**
