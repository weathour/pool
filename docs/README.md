## 为什么从 25 份并到 6 份

原来的 25 份是**同一批判断在不同轮次的产物**，后面推翻过前面：

| 原来的簇 | 问题 | 现在 |
|---|---|---|
| credit（4 份：`03`/`04`/`05`/`17`） | 连读三份会看到**三个"credit 是什么"** —— 因为我在不同轮次重新定义过 | → `02-credit.md` |
| 定位与初心（5 份：`12`/`14`/`15`/`11`/`16`） | `14` 主张分层公开，`11` 又把它推翻 | → `03-POSITIONING.md` |
| 架构与承载（6 份：`09`/`10`/`18`/`22`/`07`/`06`） | 层层叠加，同一论证写了多遍 | → `04-ARCHITECTURE.md` |
| 治理与制度（4 份：`13`/`02`/`08`/`21`） | `13` 的元老院方案**已被推翻**，但还混在里面 | → `05-GOVERNANCE.md` |
| 操作与清单（3 份：`20`/`21`/`23`） | `23` 明确被 `21` 取代；`21` 里的问题大半已定 | → `06-OPERATIONS.md` |

**合并的原则：**

1. **结论与教训一条不丢**，重复的论证只留最完整一次
2. **被否掉的方案全部保留** —— 那和"选了什么"同样重要
3. **我推翻自己的地方明确写出来**，集中到 `DECISIONS.md`
4. **旧文档不删除，全部归档** 到 [`archive/`](archive/)

## 为什么留归档

**因为"什么被排除掉了"比"选了什么"更能说明问题。**

一份只有结论没有过程的文档，读者无法判断该不该信它。
归档里保留着完整的推演过程，包括**作者想错的地方**：

- `archive/01-设计总览与体检.md` 记着"周期结算是循环引用"这个我自己写出来的矛盾
- `archive/22-git哈希方案.md` 记着 SHA-256 那条路的实测结果（三个 forge 全断）
- `archive/15-初衷与目标诊断.md` 记着"我把这个项目读窄了"的自我修正

**但归档不是给人读的** —— 它只是历史。**要读就读上面那七份。**
