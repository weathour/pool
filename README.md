# 池子

> **一个公告板加一本账。**
> 把自己攒下的资料、经验、和处理资料的方法放进一个公共的地方，并且给"想一起做事的人"一个不用互相认识也能对接的入口。

**新人先读 [`CONTRIBUTING.md`](CONTRIBUTING.md)——五分钟上手。**

| 想看什么 | 读哪份 |
|---|---|
| 五分钟上手 | [`CONTRIBUTING.md`](CONTRIBUTING.md) |
| **别人具体怎么用**（点哪、敲什么） | [`别人怎么用.md`](别人怎么用.md) |
| 完整手册（定价、冲突、故障排查） | [`CONTRIBUTORS.md`](CONTRIBUTORS.md) |
| 设计判断与被否掉的方案 | [`docs/`](docs/) |

## 在哪能找到它

| 位置 | 地址 | 说明 |
|---|---|---|
| **主仓库**（权威） | 本机自建 Gitea | 收 PR、开单、合并都在这里 |
| **公开镜像** | **https://github.com/weathour/pool** | 只读副本，方便别人看和 clone |

**★ 镜像方向是单向的：Gitea → GitHub。** 权威永远在 Gitea，
GitHub 那份是从它推过去的副本。**所以 GitHub 上的 PR 不会被处理** ——
要参与请到主仓库开 issue / PR。

镜像同步方式：每次推送到 Gitea 之后，仓库的 `post-receive` 钩子自动把它镜像到 GitHub。

**为什么要有镜像：** 镜像本身就是防篡改的一部分。**副本越多，
改账越难** —— 任何一份对不上，就说明有人动过。

## 怎么验证这个仓库

**一条命令：**

```bash
python3 tools/validate
```

它会按 `policies.jsonl` 里的 **11 条规则**逐条检查：

| 规则 | 查什么 |
|---|---|
| **p-001** | 链完整：`prev` 接得上、`seq` 不跳号、`hash` 与内容相符 |
| **p-002** | 签名有效；公钥已登记且未退役 |
| **p-003** | 复核者 ≠ 交付者；交付记录的签名者必须就是交付者 |
| **p-004** | 申请单必须写验收标准（怎么算做完了） |
| **p-005** | credit 的人工调整必须带第二人联署 |
| **p-006** | 改账不得由单人完成 |
| **p-007** | 异议必须在上限天数内被回应 |
| **p-008** | 单一来源的 credit 占比上限 |
| **p-009** | `challenge` 类型的单必须指明质疑对象 |
| **p-010** | 维护者权限变更必须公示 |
| **p-011** | 拉人进来不产生 credit |

**任何人 clone 之后跑这一条命令，就能验证整个仓库。** 不需要信任任何服务器，也不需要信任我们。

**这就是全部的可信度来源：一个哈希链加一个签名。**

**每条规则都有对应的反例测试**（`python3 tests/test_rules.py`）——
"实现了 11 条规则"这句话本身无法验证，只有"每条规则都有一个能被抓住的反例"才是证据。

## 链的锚点

**信任不建立在 git 上。** 它对 git 的对象格式没有依赖——所以即使 git 层将来
换成别的哈希方案，或者你把数据拷到 git 之外，下面这条链照样成立。

第一个提交是 genesis，`data/keyring.jsonl` 的第一条记录是它的锚：

```
keyring.jsonl 第 1 条 hash: 见下方「当期链尾」
```

**之后所有记录都链在它后面。** 签名 tag 打在周期末尾，tag 的说明里写入各份
文件的链尾哈希 —— 那是 **sha256**，与 git 用哪种对象格式无关。

### 怎么验周期 tag

```bash
git config gpg.ssh.allowedSignersFile .allowed_signers   # 一行，指向仓库里的名单
git tag -v cycle-2026-Q3
```

应当看到：

```
Good "git" signature for mr.weathour@gmail.com with ED25519 key SHA256:K/Qt…
```

**tag 的说明里还写着那一期的五份链尾哈希。** 把它和你本地算出来的对一下：

```bash
python3 tools/cycle --json | python3 -m json.tool | grep -A6 chain_heads
```

**为什么这有用：** 即使有人改了历史，他也伪造不了这个 tag ——
签名密钥不在他手里。**而 `.allowed_signers` 本身也在 git 里，改它是看得见的。**

> 为什么不用 SHA-256 git 仓库：GitHub / Gitea / GitLab **全都不支持**，
> 用了就无法推送到任何 forge。详见 [`docs/`](docs/)。

## 四条规矩

1. **只追加，不删除。** 记错了是再写一条「我改一下」，原记录永远在
2. **单子上不写人名。** 身份只在账本层，申请单是干净的
3. **不产出就衰减。** 不是把人赶出去，是让位置自己空出来
4. **不能为了让检查通过而放松检查。** 卡住了只能改事实，不能改检查

## 关于 credit

**credit 不是一个分数，是一份由三个人联署的认可记录：**

| 谁签 | 签的是什么话 |
|---|---|
| 交付的人 | "这个是我做的" |
| 复核的人 | "我看过了，它值 X" |
| 开单的人 | "它确实能用" |

**值多少由复核的人估**——他估「别人从零做出同样的东西要多久」。**定价权不在做事的人手里。**

**签名让它不可抵赖，但只防赖账，不防敷衍。** 所以还有一条：**复用次数是唯一能加分的项**——因为引用别人要先读懂它，没人会为了给别人刷分去读一个没用的东西。

**它现在什么都换不到。** 它真正有含义的那一天，是它开始决定「谁掏服务器钱」的那一天。
